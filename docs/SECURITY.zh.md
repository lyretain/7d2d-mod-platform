# 安全说明

[English](SECURITY.md) · [简体中文](SECURITY.zh.md)

本文说明工程安全控制。私密报告漏洞请遵循仓库根目录的 [安全漏洞报告政策](../SECURITY.md)，不要创建公开 Issue。

## 当前已经实施的安全措施

- manifest 使用 Ed25519 签名；
- Mod ZIP 使用 SHA-256 内容寻址；
- 客户端先验签，再使用 manifest 中的下载地址；
- 下载完成后验证文件大小和 SHA-256；
- 解压时验证 ZIP CRC；
- 拒绝绝对路径、盘符路径和 `..` 路径穿越；
- 拒绝 ZIP 符号链接、加密条目和不支持的压缩方式；
- 限制 ZIP 条目数量、单文件大小和解压总量；
- 按 Windows 大小写不敏感规则拒绝重复路径；
- 先解压到暂存目录，成功后再替换；
- 记录平台受管目录，默认不覆盖玩家私人 Mod；
- 更新前备份旧目录，失败时回滚；
- 游戏服务器只保存自己的令牌，不持有平台签名私钥；
- 后台只保存服务器令牌哈希；
- 用户密码使用随机盐和 scrypt 哈希；
- 邀请码和登录会话只保存 SHA-256，不保存原文；
- 登录失败进行按 IP 与用户名的临时频率限制；
- `ADMIN_TOKEN` 在首个用户注册后默认失效；
- 诊断请求有大小限制并执行服务端脱敏。

## 后台账户安全

- 注册必须提供未过期、未吊销且还有使用次数的邀请码；
- 管理员邀请和只读邀请使用不同角色；
- 管理邀请码原文只显示一次；
- 密码要求 10–128 位；
- 用户名比较不区分大小写，避免重复账户；
- 会话默认 7 天过期，退出后立即撤销；
- 只有紧急恢复时才临时启用 `ALLOW_BOOTSTRAP_ADMIN=true`。

密码重置、双因素认证、恢复码、账户禁用、会话撤销和持久化限流已经实现。公开部署仍应验证代理 IP 配置、2FA 恢复流程和管理员审计留存。

## 密钥信任

客户端第一次连接时采用 TOFU（首次使用时信任）保存平台公钥。以后发现公钥变化会停止更新。

正式部署推荐把可信公钥随经过代码签名的客户端更新器发布，并使用 `--public-key` 指定，避免第一次连接遭到中间人攻击。

私钥不能放在：

- 游戏服务器；
- 客户端；
- Git 仓库；
- 公共 Docker 镜像；
- 未加密的普通后台配置文件。

## DLL 风险

七日杀 Mod DLL 可以执行本机代码。即使 ZIP 和签名都正确，也只能证明它由平台发布，不能证明代码安全。

生产平台必须：

- 明确显示 ZIP 是否含 DLL；
- 要求用户确认安装第三方 DLL；
- 对 DLL 进行杀毒扫描和静态检查；
- 保存上传者、来源、许可证和审核记录；
- 支持紧急吊销问题版本；
- 不允许游戏服务器提供任意下载 URL。

## 诊断隐私

默认不要上传完整日志。客户端应只发送错误前后的有限片段，后台还会删除：

- Bearer Token；
- 密码、Secret 和 API Key；
- Windows/Linux 用户主目录；
- IPv4 地址；
- Steam/EOS 玩家标识。

当前已经提供遥测开关、诊断数据保留期限、用户删除诊断数据接口和管理员访问审计。公开社区运营仍应提供：

- 隐私说明；
- 公共实例运营者的主体与联系渠道；
- 第三方 Mod 投诉、下架与数据请求流程。

## 上线前仍需完成

- 本地主机模式和 Linux 专用服务器联机验证；
- PostgreSQL 集成、浏览器端到端和并发压力测试门禁；
- 备份恢复、回滚、密钥泄露和紧急停发的人工演练；
- 对每个公共实例实际启用 HTTPS、正式签名服务、限流、恶意文件扫描和再分发许可审核；
- 发布隐私说明和第三方内容投诉/下架流程。
